# Распределение работ: Sonnet 5.5 и Opus

Правило простое. **Sonnet** делает то, у чего в коде уже есть образец: модели, предметы, блоки, постройки, мобы, достижения, интерфейс,
сцены по готовому шаблону, проверки. **Opus** делает то, где нужно спроектировать систему с нуля или долго отлаживать неочевидное:
движки, рискованные механики, финальный босс, сложные баги. Opus также проверяет качество на контрольных точках.

Пометки: **[S]** — Sonnet, усилие high; **[S+]** — Sonnet, усилие xhigh; **[O]** — только Opus, Sonnet не трогает.
**Ждёт:** задача начинается только после указанного пункта Opus. Если он не готов, Sonnet её пропускает и берёт следующую.

## Правила для Sonnet по этому плану
- Бери задачи **строго по порядку ID**, пропуская помеченные «ждёт», если зависимость не готова (смотри HANDOFF: Opus отмечает готовность O-пунктов).
- **Одна задача — один или несколько коммитов, каждый проверен.** Не начинай следующую, пока текущая не закоммичена, не запушена и не записана в HANDOFF.
- Перед началом каждой задачи: `git pull --rebase` (Opus может работать в той же ветке).
- **Не меняй системы из колонки Opus**: движок сцен, механику времени, сеть оборотов, Безликого, небо, физику. Если для задачи их не хватает,
  запиши в HANDOFF «нужно от Opus: …» и переходи к следующей задаче.
- Если после 2–3 честных попыток что-то не выходит — откати, запиши в BUGS/HANDOFF «нужен разбор (Opus)» с тем, что пробовал, и иди дальше.
- В HANDOFF веди раздел **«Sonnet: сделано / в работе / ждёт Opus»**, чтобы на контрольной точке было видно состояние.
