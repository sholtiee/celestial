# Старт новой сессии (для Sonnet 5.5 или любой модели)

Скопируй блок ниже целиком первым сообщением в новый чат Claude Code, открытый в папке проекта.
Модель — **Sonnet 5.5**, усилие (effort) — **high**; для задач **[S+]** в `docs/SONNET_PLAN.md` — **xhigh**.
Задачи **[O]** (движки, время, Безликий, небо, сложные баги) делает Opus — для них отдельный чат на Opus с этим же сообщением,
но со словами «ты Opus, бери задачи [O] из docs/SONNET_PLAN.md».

```
Ты продолжаешь разработку Fabric-мода «Celestial» для Minecraft 26.3 (Java 25) в этой папке. Работай автономно, по-русски, кратко.

ПРОЧИТАЙ ПЕРЕД РАБОТОЙ (по порядку, целиком):
1. AGENTS.md — правила, устройство кода, команды сборки и проверки, грабли API 26.3 и автопилота.
2. HANDOFF.md — текущий статус; раздел «▶ Точка продолжения» — откуда начинать.
3. docs/ROADMAP.md — план волн до 1.0.
4. docs/LORE.md — библейский лор «Летопись Небес». Главное: §0 (лор ИГРАЕТСЯ, а не читается), §5a (пролог), §5b (эпизоды), §5c («Отблески» — воспоминания на ходу).
5. docs/BUGS.md, docs/PUZZLES.md — по мере надобности.

ЖЁСТКИЕ ПРАВИЛА ПОЛЬЗОВАТЕЛЯ:
- Звук в dev-клиенте выключен (tools/autopilot.sh ставит soundCategory_* в 0). Не включай.
- Никакого ванильного арта: все текстуры, модели, постройки, звуки — только генераторами tools/gen_*.py (от ванили можно брать лишь альфа-маску формы). JSON в src/main/resources руками не правь — меняй генератор и запускай bash tools/build_assets.sh.
- Не выдумывай результат. «Проверено в игре» пиши только если сам видел: скриншоты открывай Read'ом, результаты команд смотри в build/client.log. Иначе честно: «проверено только компиляцией».
- Оформление репозитория (README с картинками, лицензия, релизы, CI) отложено — не трогай.
- Цель — мод «максимального уровня»: свои модели с анимацией и светящимся слоем, эффекты, защита загадок от обходов. Новое делай сразу по этой планке.
- Лор: Бог и Христос не изображаются; цитаты только из Синодального перевода и KJV; повествование — играбельными сценами и воспоминаниями, текст — не больше ~20%.

ЦИКЛ НА КАЖДЫЙ ШАГ (обязателен):
1. Код + генератор → bash tools/build_assets.sh → python3 tools/qa/lint_assets.py (должно быть «Итого находок: 0»).
2. JAVA_HOME=/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home ./gradlew build
3. tools/devserver.sh "команда" sleep:5 — нет ошибок регистров и датапака.
4. Сценарий автопилота tools/scenarios/<шаг>.txt (части «Честно» и «Обход» для загадок, метки /say TEST …) → TIMEOUT=600 tools/autopilot.sh … → grep "Проверка пройдена|неуспешна|Exception" build/client.log → скриншоты склей python3 tools/contact.py и посмотри сам.
5. Коммит на русском с подробным телом (в конце строка Co-Authored-By для своей модели) → git push → обнови HANDOFF.md (чек-лист, «Точка продолжения»), docs/BUGS.md / PUZZLES.md.
Коммить и пушь часто: после каждого законченного и проверенного шага.

КАК РАБОТАТЬ, ЧТОБЫ НЕ СЛОМАТЬ:
- Перед новым кодом найди похожий готовый и повтори его приём (модели — client/render/HeavenModels.java + tools/gen_heaven_mobs.py; боссы — boss/FrostArchon.java + boss/BossIntro.java; загадки — block/puzzle/* + puzzle/PuzzleZone; достижения — tools/gen_achievements.py).
- API Minecraft ищи в .mcsrc/ (grep), не угадывай. Если .mcsrc нет — tools/setup_mcsrc.sh.
- Не меняй генерацию мира без проверки: после правки — rm -rf run/saves/test/dimensions/celestial/<мир>, сценарий облёта, python3 tools/qa/scan_world.py --dim celestial/<мир>.
- Если гипотеза не подтвердилась — откати правку, запиши находку в docs/BUGS.md, не оставляй «на всякий случай».
- Застрял на одной проблеме после 2–3 честных попыток — запиши в HANDOFF «нужен разбор (Opus)» с тем, что пробовал, и переходи к следующему пункту.
- В конце каждой сессии (или когда лимит близок) — всё закоммить, запушить и обновить «Точку продолжения» в HANDOFF так, чтобы следующий чат начал без вопросов.

ТВОЙ ПЛАН — docs/SONNET_PLAN.md (прочитай целиком; задачи [O] не трогай, задачи «ждёт O…» пропускай, пока Opus их не закрыл — это видно в HANDOFF).
Начинай с первой невыполненной задачи по порядку ID (S1.1, S1.2, …). Перед каждой задачей — git pull --rebase.
Твою работу потом проверит и исправит Opus: по каждой задаче записывай в HANDOFF («Sonnet: сделано») ID, коммиты, сценарии, ключевые скриншоты, что проверено в игре, а что только компиляцией, и известные недочёты.

Начни с чтения файлов, затем кратко (5–10 строк) скажи, с какого пункта начинаешь, и приступай без ожидания подтверждения.
```

## Заметки для пользователя
- **Распределение работ** — `docs/SONNET_PLAN.md`.
- **Справится ли Sonnet 5.5:** с рутинной частью — да, хорошо. Это модели мобов по образцу, предметы, достижения, постройки,
  сценарии, баги с понятной причиной: паттерны в коде уже есть, правила и проверки расписаны. Слабее он там, где нужен
  крупный дизайн с нуля и долгая отладка неочевидного: движок сцен, механика времени, финальный босс, небо, загадки вроде BUG-063.
  Ещё у него ниже точность оценки картинки по скриншоту. Для пунктов с ⚠ лучше Opus или хотя бы xhigh, плюс просмотр результата.
- **Как контролировать:** раз в несколько сессий читай «Точку продолжения» и последние коммиты (`git log --oneline -15`).
  Если в коммитах часто «проверено только компиляцией» на визуальных вещах — попроси прогнать сценарии и показать скриншоты.
- **Если сессия оборвалась на середине:** новый чат с тем же стартовым сообщением подхватит работу по HANDOFF.
